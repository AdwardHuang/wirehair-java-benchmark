# Wirehair JNI for Java 17+

This project provides a Java API around the native [Wirehair](https://github.com/catid/wirehair) fountain-code library. The release JAR is intended to contain both native binaries and extract the correct one at runtime.

## Build and download the multi-platform JAR

The workflow `.github/workflows/package-jar.yml` builds x86-64 Windows and Linux native libraries independently, combines them under `src/main/resources/native/`, then creates:

- `wirehair-jni-1.0.0.jar` — Java API plus `wirehairjni.dll` and `libwirehairjni.so`
- `wirehair-jni-1.0.0-sources.jar` — Java source
- `wirehair-jni-1.0.0-javadoc.jar` — generated API documentation

Run **Actions → Build Wirehair JNI multi-platform JAR → Run workflow**. Download the `wirehair-jni-jar` artifact from the completed workflow. The regular native benchmark workflows remain available for performance testing.

> The native binaries are generated by CI, not committed as fake/empty resource files. The universal JAR is only produced after both native builds succeed.

## Maven dependency

After installing the JAR into a local Maven repository:

```xml
<dependency>
    <groupId>com.hrz</groupId>
    <artifactId>wirehair-jni</artifactId>
    <version>1.0.0</version>
</dependency>
```

Or use the JAR directly on the classpath. Runtime only requires a compatible Java 17+ JVM and a supported platform/architecture.

## API example

```java
import com.hrz.wirehairbench.Wirehair;
import com.hrz.wirehairbench.WirehairEncoder;
import com.hrz.wirehairbench.WirehairDecoder;
import com.hrz.wirehairbench.WirehairDecodeStatus;

import java.security.MessageDigest;
import java.util.Arrays;

public class WirehairExample {
    public static void main(String[] args) throws Exception {
        byte[] message = "Hello Wirehair".getBytes(java.nio.charset.StandardCharsets.UTF_8);
        int blockBytes = 1024;
        byte[] recovered;

        // Native library is extracted from the JAR and loaded automatically.
        Wirehair.load();

        try (WirehairEncoder encoder = Wirehair.encoder(message, blockBytes);
             WirehairDecoder decoder = Wirehair.decoder(message.length, blockBytes)) {
            // This example sends the same source/repair IDs in order. In a real transport,
            // preserve each block ID in the packet and pass that ID to decoder.accept().
            WirehairDecodeStatus status = WirehairDecodeStatus.NEED_MORE;
            int maxBlocks = 1000;
            for (int blockId = 0; blockId < maxBlocks; blockId++) {
                byte[] packet = encoder.encode(blockId);
                status = decoder.accept(blockId, packet, packet.length);
                if (status == WirehairDecodeStatus.READY) {
                    break;
                }
            }
            if (status != WirehairDecodeStatus.READY) {
                throw new IllegalStateException("More source/repair packets are required");
            }
            recovered = decoder.recover();
        }

        if (!Arrays.equals(message, recovered)) {
            throw new AssertionError("Recovered bytes do not match input");
        }
        System.out.println("Recovered " + recovered.length + " bytes successfully");
    }
}
```

## Public API summary

- `Wirehair.load()` — load the bundled platform library and initialize Wirehair.
- `Wirehair.encoder(byte[], int)` — create an encoder; close it with try-with-resources.
- `Wirehair.decoder(long, int)` — create a decoder for the original message length and block size.
- `WirehairEncoder.encode(int)` — encode one source/repair block and return its exact byte array.
- `WirehairEncoder.encodeInto(int, byte[])` — encode into a reusable buffer to reduce Java allocations.
- `WirehairDecoder.accept(int, byte[], int)` — submit a received packet with its original block ID; returns `NEED_MORE` or `READY`.
- `WirehairDecoder.recover()` / `recoverInto(byte[])` — recover the original bytes after the decoder reports `READY`.
- `Wirehair.memoryStats()` — current and peak process RSS/working set in bytes.

All public API methods include Javadoc. Native encoder/decoder instances own native memory and must be closed. Always validate recovered content (for example using SHA-256) at the application protocol layer.

## Runtime library selection

The loader automatically selects:

- Windows x86-64: `native/windows-x86_64/wirehairjni.dll`
- Linux x86-64: `native/linux-x86_64/libwirehairjni.so`

To load a specific native library instead of the bundled one, set `-Dwirehairjni.path=/absolute/path/to/wirehairjni.dll` or the corresponding `.so` path.

Unsupported OS/architectures fail fast with an `UnsatisfiedLinkError`. This release does not claim ARM64 or macOS support.

## Local native build

Use `build-windows.bat` on Windows or `build-linux.sh` on Linux to build the native library for the current machine. Those scripts require CMake, a C++ compiler and JDK 17. The full multi-platform JAR requires both binaries and is assembled by the `package-jar.yml` workflow.

## Native API and error handling

`WirehairDecodeStatus.NEED_MORE` means additional encoded packets are required. `READY` means the native decoder reports sufficient information for recovery; applications should still verify the recovered bytes. Native failures are surfaced as `WirehairException` by the high-level API. `WirehairNative` remains available as a documented low-level JNI bridge.
